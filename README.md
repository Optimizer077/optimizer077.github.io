# Academic Portfolio — Static Site

A lightweight static academic website. Pure **HTML + CSS + vanilla JS** — no build step, no frameworks, deploys directly to GitHub Pages.

---

## Pages

| File | Purpose |
|---|---|
| `index.html` | Home page — bio, research interests, news, publications, projects, honors |
| `reading.html` | Paper reading list, auto-populated from Zotero CSV exports |
| `seminar.html` | Lab seminar slide decks (Google Slides embeds) |

---

## Reading List

Papers are loaded from CSV files in the repo root. Each CSV maps to one section in `reading.html`:

| CSV file | Section |
|---|---|
| `Autonomous_Drive.csv` | VLN / VLA / Autonomous Driving |
| `vlm.csv` | Vision-Language / Multimodal Models |
| `reasoning.csv` | Reasoning Models |
| `token.csv` | Token Reduction |
| `diffusion.csv` | Diffusion Models |
| `inr.csv` | Implicit Neural Representations |
| `retrieval.csv` | Instance Retrieval |
| `mri.csv` | MRI Papers |
| `hyperspectral.csv` | Hyperspectral Imaging |
| `misc.csv` | Misc / Interesting Papers |

`assets/js/reading.js` fetches each CSV at page load, merges papers that appear in several topics, and renders a searchable list with topic chips, a papers-per-year chart (click a bar to filter), a "recently added" strip (from Zotero's `Date Added`), and abs/PDF/DOI links. Filters are kept in the URL hash, e.g. `reading.html#q=diffusion&topic=vlm`. No build step required.

---

## Syncing from Zotero

Run `zotero_sync.py` to refresh the CSVs directly from your local Zotero library:

```bash
# Refresh all sections silently
python zotero_sync.py --refresh

# Interactive — choose which sections to update
python zotero_sync.py
```

Requirements: Python 3 (stdlib only). Zotero must be installed locally. The script copies the Zotero SQLite to a temp file so Zotero can stay open while syncing.

After running, commit and push the updated CSV files to publish changes.

## Background physics, the portrait, and on-device Gemma

`assets/js/bg-physics.js` draws the page background on the GPU (WebGL2) and plays **30 processes** from physics, dynamics
and machine learning, defined in `assets/js/bg-scenes.js`. Each visit opens on a random one (never the one shown last,
remembered in localStorage). Every 9 s it moves to the next in a shuffled bag, so all 30 play once before any repeats and
then the loop starts over. The portrait (`pixel-hero.js`, effects in `hero-effects.js`) plays the same process on the
photo; under it the page shows the process name, its equation (typeset as MathML) and a counter, and **↻ next** skips ahead.

| Process | Background (particles) | Portrait (pixels) |
|---|---|---|
| Flow | curl-noise velocity field, stirred by the cursor | carried along the field, then back |
| Diffusion | a ring / S-curve / spiral is noised, `xₜ = √ᾱₜ x₀ + √(1−ᾱₜ) ε`, then denoised | noised, then denoised back |
| Heat equation | Brownian particles over an analytic heat kernel; the cursor adds heat | colours blurred by `∂ₜu = α∇²u`, then un-blurred |
| Lorenz | relax onto the Lorenz attractor | pulled onto it and back |
| Flow matching | straight-line paths between noise and data | straight paths to noise and back |
| Langevin dynamics | noisy gradient descent in a loss landscape | rolls into the wells and back |
| Wave equation | ripples from point sources | ripples across the photo |
| Point vortices | advected by three moving vortices (Biot–Savart) | twisted by a vortex, then unwound |
| Gravity | orbits around a central mass | bent into an Einstein ring (point-mass lens equation) |
| k-means | points join the nearest of five moving centroids | colours clustered (k = 6, Lloyd) |
| Rössler | the Rössler attractor | pulled onto it |
| Clifford map | the iterated map, parameters breathing slowly | each pixel follows its own orbit |
| Double pendulum | 10⁵+ pendulums that differ by a hair: the butterfly effect | pixels move with their pendulum tips |
| Double gyre | dye stirred by the double-gyre flow | pixels advected along it |
| Van der Pol | drops spiral onto the limit cycle | pixels follow phase-plane trajectories |
| Chaos game | halfway jumps to polygon vertices: Sierpiński triangle, pentaflake, hexaflake | pixels hop toward triangle vertices |
| Lévy flights | 80 walkers with power-law steps, particles draw their recent path | pixels take Lévy steps |
| MCMC | Metropolis walkers settle into a banana, ring or three blobs | tempered Metropolis walk into a banana |
| Kuramoto | oscillators on rings lock into step once the coupling passes `K_c = 2γ` | pixels revolve, then lock into a spoke |
| Chladni | sand collects on the nodal lines of a vibrating plate | pixels slide to the nodal lines |
| Double slit | particles go through one slit and land in interference fringes | pixels land in fringes |
| Cyclotron | gyration plus E×B drift; both charge signs drift the same way | cycloid loops |
| Phyllotaxis | seeds placed at the golden angle, slightly detuned later | pixels take sunflower seats by brightness |
| Lissajous | `x = A sin(at+δ)`, `y = B sin(bt)` with a comet running along it | pixels line up along the curve |
| Monte Carlo π | darts in a square, inside the inscribed ellipse vs outside | pixels thrown at random and tinted |
| Galaxy | differential rotation winds a bar into spiral arms | portrait wound up with Ω ∝ 1/r |
| Optimal transport | a uniform disk moves onto an annulus without crossings | pixels re-sorted by brightness |
| Brownian bridge | 420 random paths pinned at both ends | pixels take bridge excursions |
| Fountain | jets of drops on parabolas | pixels thrown up on parabolas |
| Cosmic web | Zel'dovich approximation, `x = q − D(t)∇Φ(q)`; caustics form | pixels displaced by it |

Each scene is two short GLSL snippets (a state update and a colouring) that the engine wraps into its own pair of
programs, compiled lazily and in parallel while the previous scene plays. Its GPU cost is kept near **5% of the frame
budget**: with `EXT_disjoint_timer_query_webgl2` the particle count is steered by measured GPU time (cap ≈1M on
desktop, ≈262k on phones); without it a modest fixed count is used and reduced if frames drop. It pauses when the tab is
hidden, and `flow-field.js` (2D canvas) takes over if WebGL2 is unavailable. In the browser console, `__bg.stats()` shows the
current scene, its position in the round, the particle count and GPU share; `__bg.scene('rossler')` jumps to a scene.

To add a process, give it the same id in three places: a caption and formula in `PROCESSES` in `build_math.py`, a scene in
`bg-scenes.js` (the header comment of that file explains the two GLSL snippets) and an effect in `hero-effects.js`. Then run
`python build_math.py` and `python stamp_assets.py`; the round-length counter picks the new process up by itself.

### Equations and citations

`build_math.py` (Python, standard library only) turns the LaTeX written in it into MathML, which browsers typeset
natively, so no maths library is loaded. Run `python build_math.py` after editing it: it rewrites `assets/js/processes.js`
(process names and formulas for the portrait) and the blocks between the `<!--math:…-->` and `<!--cite:…-->` markers in
`index.html` (each publication's key equation and its BibTeX "Cite" panel with a copy button).
`python build_math.py --check` only parses everything. The I-INR and DescanDiffusion equations are quoted from their
papers; the FCRN and KMBE ones are marked "schematically" because those papers' full text was not available to check.

### Ask Gemma (the side tab on the homepage)

The **Ask Gemma** tab sits on the right edge of the homepage, the reading list and the seminar page, at every screen
size. The first click loads three files listed in its `data-scripts` attribute (`ali-facts.js`, `gemma-rag.js`,
`gemma-chat.js`; `stamp_assets.py` fingerprints them like the other assets) and opens a panel to the left of the tab.

**Instant answers need no download.** `gemma-rag.js` reads the homepage's text (About, news, learning, side projects,
publications with their equations and captions, patents, projects, honors) plus `ali-facts.js`, splits it into passages
of at most 520 characters and ranks them for a question with BM25 (light stemming, stop words, a few intent
expansions such as "from" → nationality, "paper" → publications). Without the model, the panel shows the best passages
and a "From:" row of links. On the homepage the passages come from the live DOM and a link scrolls to the passage and
marks it; on the other pages `index.html` is fetched once and read the same way, and a link opens the homepage section.
Editing the homepage therefore updates what the chat knows; only `ali-facts.js` needs editing by hand, for things the
page does not say in one place. A question about something the page does not mention gets no passages and the reply
"I could not find that on this page", not the nearest topic.

**Optional on-device model.** *Download & run* (*Load Gemma* once the model is saved) fetches
[`litert-community/gemma-4-E2B-it-litert-lm`](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm)
(`gemma-4-E2B-it-web.task`, ~2.0 GB, Apache-2.0) and runs it with `@mediapipe/tasks-genai@0.10.29` on WebGPU. Before
anything is downloaded it warns about size, battery and memory (with extra warnings on phones and metered
connections). The model is saved in the Origin Private File System after the first download and runs entirely in the
browser. With the model loaded, each question is answered from the retrieved passages (the prompt keeps to 1300 of the
model's 2048 tokens: the weakest passage is dropped first, then the oldest exchange). The system prompt states that Ali
is from Pakistan and is not Korean, because the page mentions Korea often (Kyung Hee University, a Korean patent).

To test the prompt without the 2 GB download, set `window.__gemmaMock = { sizeInTokens, generateResponse, … }` before
clicking *Load Gemma*; the chat then uses that object in place of the model.

## Local Preview

```bash
python -m http.server 8080
```

Then open `http://localhost:8080`. (Direct `file://` access may block CSV fetches in some browsers.)

## Deployment

1. If you changed an equation or a BibTeX entry in `build_math.py`, run `python build_math.py` first.
   Then, if you changed `style.css` or anything in `assets/js/`, run `python stamp_assets.py`. It adds a content
   fingerprint (`?v=…`) to those links so phones and browsers download the new files immediately instead of
   using a cached copy.
2. Push to the `main` branch — GitHub Pages serves the site automatically (desktop and mobile are the same
   responsive pages).
